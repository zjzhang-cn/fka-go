#【部署】Go module `github.com/zjzhang-cn/fka-go`，**仓库根就是模块根**（没有 go/ 那一层），产出两个静态二进制：`bin/fka`（入口 ./cmd/fka）与 `bin/fka-memory`（入口 ./mcp/memory）。`make build` 编译（每个构建目标显式 `CGO_ENABLED=0`）；`make verify` 是提交前闸门（fmt-check → vet → test → build → smoke，smoke 在 .smoke/ 隔离安装根里装一个技能与一个记忆 server，断言 `fka tools` 真列出 skills__load/skills__list/mcp__memory__search_memories/mcp__memory__remember_memory **并且**库落在 mcp.json 的 cwd 指定处）；`make login` 扫码登录 iLink 并把凭证写进 `<安装根>/.env`（0600）；`make serve` 常驻接微信收消息；`make release` 交叉编译 6 平台到 dist/。**安装根 = $FKA_HOME → 可执行文件所在目录 → cwd**，data/ logs/ .env mcp.json skills/ 全按它解析——直接跑 `./bin/fka` 时安装根是 `bin/`，而 `make serve` 把 FKA_HOME 设成仓库根，两种跑法读的不是同一份配置。
#【系统】fka-go 是一个「工具调用 agent + 一个渠道接缝」：模型自己决定调哪些工具、循环到得出答案为止（internal/agent），业务层只认 internal/llm、internal/tools、internal/channels 三条契约，**唯一装配点是 internal/app**（构造函数链，没有 cordis.yml）。**它自己不拥有任何数据、也不带任何内置能力**——能力只有两条来源：`<安装根>/mcp.json` 里的 MCP server（stdio 子进程或 HTTP）与 `<安装根>/skills/<名字>/SKILL.md`；微信 iLink 只是接缝上的一个 Provider。依赖只有 4 个直接依赖且全部纯 Go。顶层不可破的原则：① **零 CGO**（漏了不报错，只产出一个换台机器就跑不起来的二进制；`fka version` 的 cgo 行由 build tag 判定）；② **两条靠 AST 扫描守的边界**——`mcp/memory/**` 不许 import 本仓库树外的任何包、`internal/channels` 不许 import 任何具体渠道，破了都只静默失效（照常编译、照常跑）；③ **权限过滤必须留在 SQL 的 WHERE 里**（`viewer_wxid` 是模型填的工具参数，server 按决定不做进程级绑定，提示注入是结构性暴露且失败时不报错）；④ **会话历史逐字重放**（`tool_calls.arguments` 保持原始 JSON 字符串，历史只从最老整组丢弃、绝不改写留下的，因为 provider 的前缀缓存认「从第一条起逐字不变的前缀」）；⑤ **MCP server 启动后 stdout 一个字都不能有**，那是 JSON-RPC 通道；⑥ **可选能力缺失一律降级不阻断**（没配模型、没 MCP、没技能、渠道起不来都只让对应能力缺席，不让服务起不来）。

#条目格式: 文件名[标签]: F:功能 | R:关联 | A:接口 | S:信息;单行;四段齐备;无内容用 - 占位
#F 口径: 写一个简短明确的核心功能锚点,通常控制在10个字以内;语义完整优先,确有需要可以适度超过;禁止翻译文件名、堆砌多个职责或使用批量模板句
#R 口径: 只列跨文件强依赖(逗号分隔精确路径或模块名);日志/通用工具/框架自带不列;不得机械复制import或依赖清单
#A 口径: 只列本文件对外提供的API、入口或契约;内部函数不列;无则写 -
#S 纪律: 只写「文件名+标签+F+R+A推不出,但模型理解系统或修改代码时必须知道」的信息;两问皆是才写;禁演进叙事、禁时间维度(版本/日期/修复痕迹);字数配额见下方S配额行
#多标签体系: 大型项目可为不同技术域(如后端/前端/数据库)各立一套独立规范区块,各自定义 A/B/D 取值;同一字母在不同体系含义可以不同,但须在各自区块内声明清楚
